## 目标

给默认星形网络加第四个节点：一个位于**中心所在网络内部**的 worker。它和中心之间没有跨网出口，所以两个方向都不计费——这是它和两个远端站点唯一的实质差别。

- `sim/starmap.go`
- `sim/starmap_test.go`

## `sim/starmap.go`

1. 在 ID 常量块里加一个：
   ```go
   CentreWorkerID = core.NodeID("node4")
   ```
   沿用 `CentreID` / `SiteAID` / `SiteBID` 的命名风格。网络名复用已有的 `centreNet`，不再新增常量。

2. `DefaultNodes()` 里加进去 → 默认网络变成 4 个节点（1 个中心 + 3 个叶子）。

3. `DefaultUpLinks()` 加一条：
   ```go
   CentreWorkerID: link(0, "intra-net", centreNet),
   ```

4. `DefaultDownLinks()` 加同一条（两个方向都免费，因为它根本没离开这个网络，不产生出口费）。

5. **策略名故意不叫 `"local"`。** 中心的自身条目 `"local"` 含义是「同机、无需传输」，而这个 worker 是**另一台机器上的真实传输**，只是便宜。目前 `core.Link` 只暴露 `Cost()`，两者的 cost 都是 0，所以**这个策略名是唯一能区分它们的东西**——合成一个名字就等于宣布它们是同一件事。

6. 更新文档注释：说明第四个节点是什么、为什么同网络免出口费，以及 5 里那条区分。

## `sim/starmap_test.go`

新增一个测试，钉住这个节点的性质：两个方向都免费、位于 `centre-net`、且策略名与中心的自身条目**不同**。

已有的 `TestDefaultStarMapIsTotal` 和 `TestDefaultStarMapLinksAreUsable` 是遍历 `sm.Nodes` 的，所以自动覆盖新节点，不用改；`TestDefaultStarMapDirectionsDiffer` 显式枚举 SiteA/SiteB，也不受影响。

## 明确不做，但你应该知道（要的话说一声）

- **`core.Link` 仍然没有延迟和带宽访问器。** 因为只暴露 `Cost()`，这个新节点和中心的自身条目之间，差别**只有一个策略名字符串**——0.2ms / 10Gbps 和「没有链路」长得一模一样。加上 `Latency()` 和 `BandwidthBps()` 才能让它真正有意义，而且这是**唯一能解封迁移时间计算**的改动：1.9 GB 的 KV cache 走 100 Mbps 上行是几分钟的墙钟时间，而那个数字正是 locality 值钱的主要原因。
- **`core/place.go` 的平局判定不确定。** `for nodeID := range sm.Nodes` 遍历的是 map，得分相等时赢家随机。多出一个分数容易和中心相等的节点，会让这个问题更容易显形。修法是写明平局规则（比如取最小 NodeID）或遍历前排序。

这两条都属于改 `core`，超出了你这次的指令范围，所以我不动。
